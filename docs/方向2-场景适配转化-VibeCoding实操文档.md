## 1. 想清楚：唯一亮点是什么

### 1.1 一句话定义

**「同帖千面」的场景迁移引擎 —— 别人的方案，换个场景就失效；我们让它按你的场景重新长一遍。**

> **真正差异化澄清（2026-09-09 产品推演）：** 单次"贴帖+填场景→AI出方案"与通用 AI 配好 prompt 无本质区别；本产品真正资产是**同一篇帖被无数真实场景持续填充后形成的"场景应用网 / 知识应用图谱"**——通用 AI 每次对话都是孤岛，没有"别人在同处境下得到了什么"。差异化在**累积**，不在单次交互。

### 1.2 痛点链条（30 秒能讲完）



1. 用户收藏一篇经验帖，潜台词是 "以后我遇到类似问题要用"；

2. 但帖子是作者在**他的器件、他的约束、他的环境**下写的；

3. 读者真遇到问题时，场景已经变了，照搬必翻车，又不会自己改，于是收藏夹落灰；

4. **我们补上最后一步：告诉 AI"我的场景"，它自动对比差异、指出照搬风险、给出一步步可执行的迁移方案。**

### 1.3 为什么这一个亮点就够（差异化）



| 对比对象        | 它们在做什么                       | 我们在做什么                               |
| ----------- | ---------------------------- | ------------------------------------ |
| 90% 知识类参赛作品 | 长文→摘要 / 卡片 / 分类（**压缩**，面向过去） | A 场景方案→B 场景方案（**迁移**，面向你未来的问题）       |
| 通用大模型直接问    | 给一段泛泛的通用回答                   | 以**原帖方案为基准**，逐条对比 "哪里不一样、为什么要改、改成什么" |
| 收藏夹本身       | 只存不用                         | 让每篇收藏对每个不同处境的读者重新产生一次价值              |

> **核心记忆点（路演反复强调）：别的作品回答 "这篇文章讲了什么"，我们回答 "这篇文章对 ' 我' 该怎么用"。**

> **补充记忆点（回应"和直接问 AI 有何区别"）：** 我们不声称是 AI 神谕，而是"真实场景 × AI 起草 × 人验证"的网络。单篇帖积累的真实场景越多，这张网越能交叉验证、越准。

> **产品愿景：** 当一个新的用户来到这里，收到了这篇帖子，遇到了这个问题。在众多的真实应用场景下，你总能找到与你的真实场景相符合的解决方法，这样才能真正解决这个问题。当任何人遇到这个问题都能真正解决时，这个帖子的价值才真正发挥到了极致。

### 1.4 杀手锏演示手法：「一帖两吃」

内部展示时，用**同一篇帖子、连续输入两个截然不同的场景**，现场生成两份完全不同的方案 —— 评委 / 队友 30 秒内就能看懂 "场景迁移" 的威力。示例（§10 有完整素材）：



* 同一篇《STM32 串口通信踩坑》：


  * 场景 A「智能车双串口 + 115200 高速摄像头」→ 方案走向 **DMA + 双环形缓冲**；

  * 场景 B「电池供电水表、单串口、要求低功耗」→ 方案走向 **空闲休眠 + 接收唤醒 + 降波特率**。

* 一篇原帖，两种解法，差异和对策都能追溯到原帖。**这就是整个 Demo 的高潮，所有页面都为这 2 分钟服务。** 演示除现场两吃外，方案库应**预置同一帖的更多场景**（不止 A/B 两吃），让评委一眼看到"一帖千面"的网感，而非仅两次生成。

## 2. 官方 API 可行性（已核验，结论：可行）

> 依据赛方下发的官方 
>
> `zhihu-cli v0.2.1`
>
>  接口文档（2026-07）。只列与本亮点有关的。



| 用途        | 端点                                                                  | 关键返回                                                   | 日免费额度 |
| --------- | ------------------------------------------------------------------- | ------------------------------------------------------ | ----- |
| 拉我的收藏夹    | `GET /api/v1/user/favlists`                                         | 收藏夹 UrlToken / 标题                                      | 共享池   |
| 拉夹内内容     | `GET /api/v1/user/favlist_contents?FavlistUrlToken=&Offset=&Limit=` | 标题 Title、摘要 Summary、Url、收藏时间 FavTime、作者                | 共享池   |
| 近期收藏      | `GET /api/v1/user/collections?Limit=`                               | 同上（无分页，只是最近一批）                                         | 共享池   |
| 标题反查补全文   | `GET /api/v1/content/zhihu_search?Query=&Count=`                    | ContentText 长摘要、权威等级、精选评论                              | 5000  |
| **AI 推理** | `POST /v1/chat/completions`（**OpenAI 兼容**）                          | model 选 `zhida-thinking-1p5`（深度推理）/`zhida-fast-1p5`（快） | 100   |

**四个关键事实：**



1. 鉴权只需一个请求头 `Authorization: Bearer <Access Secret>` + `X-Request-Timestamp: <秒级时间戳>`；**本地&#x20;**[localhost](https://localhost)**&#x20;就能读你自己账号的收藏，不需要 OAuth、不需要部署**。

2. 收藏接口**只给摘要不给正文**，用知乎搜索按标题反查 `ContentText` 补全（合规、非爬虫）；补不到就用摘要，不影响主链路。

3. 直答接口是 OpenAI 协议，等于白送一个后端 LLM，且 "用知乎模型处理知乎内容" 叙事更顺；每天 100 次，**调试期一律用 Mock 省额度**。

4. 响应是 PascalCase（Code/Data/Items），分页 NextOffset 是字符串；错误码 20001 鉴权 / 30001 频控 / 30002 配额，要做友好降级。

**赛前一次性准备（30 分钟）：**



1. [https://developer.zhihu.com/profile](https://developer.zhihu.com/profile) 申请 Access Secret（只显示一次，存好，绝不进 Git / 前端）。

2. 用 Apifox/curl 各调一次 collections、zhihu\_search、直答，确认通。

3. 用自己账号收藏 3 篇工科经验帖（素材见 §10）。

## 3. 最小可行范围（防止做着做着发散）

### 3.1 P0 唯一主链路（做到这个就赢了内部比选）



```
收藏台：看到我收藏的经验帖（真实 API / 演示数据一键切换）

&#x20;  → 点「适配到我的场景」

场景适配工作台：

&#x20;  上：AI 自动解构「原帖场景/原方案/约束/适用边界」

&#x20;  下：我填「我的场景 + 约束」（带一键填入示例）

&#x20;  → 点「生成我的方案」

结果三件套：

&#x20;  ① 差异对比（相同点 / 逐条关键差异 / 照搬风险）

&#x20;  ② 我的定制方案（3\~6 步，每步注明"因为哪条差异而改"，附参数）

&#x20;  ③ 一句话总结（相比原帖最关键的改动）

&#x20;  → 存入「我的方案库」，可回看/复制
```

> **P0 主链路的范围硬约束（2026-09-09 推演补入）：**
> - **入口质量门**：只有"含真实可迁移解法"的帖进入迁移 corpus；低于质量阈值（赞/藏/作者等级/盐选/专业领域）或非解法类（提问/吐槽/新闻/废话）帖不进入，读者可标"无可迁移解法"踢出。垂直优先吃工科专业技术内容。
> - **低门槛输入三态**：场景输入至少支持 ①粘贴代码/报错/截图→AI 反推 ②结构化填空(芯片/下拉/多选) ③AI 反问 2–3 个选择题。禁止只给一个空白大文本框。
> - **人环验证状态**：每份方案带验证状态字段（AI 草稿 ↔ N 人验证通过），支持"标记不准 / 补充实测"。验证网同时兜 AI 答案不准与原帖根不准。

### 3.2 明确不做清单（别人的方向 / 多余功能，全部砍掉）

> **精细化口径（2026-09-09 推演补入）：** 禁的是"gamified 刷量式"功能与无关方向；**允许"质量驱动的影响力反馈"（非积分）**——它是场景网成型的命门，但必须质量门控，避免刷量灌低质反噬引擎（见 §19、§20）。

* ❌ 荧光笔标注、批注（那是方向 1，本 Demo 原文由 AI 自动解构，不需要用户动手标）

* ❌ gamified 积分 / 等级 / 成就徽章 / 技能树 / 成长值（方向 3 的刷量模式；与"网要贡献成型"冲突，放开会灌低质反噬引擎）

* ✅ **允许（非积分）质量驱动的影响力反馈**：场景网归属感（"你加入第 N 个场景"）、同类对照好奇（"看看别人同处境"）、creator 反哺提示（"你的回答被应用到 N 场景"）。机制见 §20.2.3，仍受 §20.1 质量门约束。

* ❌ 知识卡片、复习、艾宾浩斯、答题（通用知识库套路，同质化）

* ❌ 登录注册、多用户、OAuth（单人演示用自己账号的 Access Secret 即可）

* ❌ 移动端、个人设置、**外部社交分享**（内部场景网可见性见 §20.2.3，不算外部分享）

* ✅ **深色炼金主题**：本 Demo 的视觉风格（非不做项）；仅不做"多主题切换 / 浅色模式"。

* ❌ 在线部署（内部演示本地跑；入选后再谈部署）

### 7.1 `zhihu/client.py` 函数签名（定死）



```
async def list\_favlists(limit=20) -> list\[dict]

async def list\_favlist\_contents(url\_token, offset="0", limit=20) -> dict  # {items,paging}

async def list\_recent\_collections(limit=20) -> list\[dict]

```



* 统一超时 20s；30001 等待 1.5s 重试 1 次；30002/20001 抛中文业务异常，上层自动切 Mock。

* `USE_MOCK=true` 时前四个返回 `mock_zhihu.py`，`zhida_chat` 返回 `mock_llm.py`。

* 日志只打 Secret 前 4 位 +\*\*\*，严禁打印全量密钥。

### 7.2 `zhihu/adapter.py` 字段映射（PascalCase → camelCase）



```

&#x20; "FavTime":"favTime","LikeCount":"likeCount","CommentCount":"commentCount",

&#x20; "FavoriteCount":"favoriteCount","Title":"title","Summary":"summary"}

AUTHOR = {"Name":"authorName","Headline":"authorHeadline","Url":"authorUrl"}

SEARCH\_ITEM = {"Title":"title","ContentID":"contentId","ContentText":"contentText",

&#x20; "Url":"url","VoteUpCount":"voteUpCount","AuthorName":"authorName",

\# 精选评论 CommentInfoList\[].Content -> comments: \[str]

```

### 7.3 标题反查补全（`POST /api/sources/{id}/enrich`）

按 title 调 zhihu\_search (count=3) → 取 ContentText 最长 / 权威等级最高者 → 回写 content\_text；失败置 failed，保留摘要，不阻断。

### 7.4 省额度策略

A1 解构结果按帖子缓存（同一篇只调 1 次，用 fast 档）；一次适配只额外调 A2、A3（thinking 档）。同一篇帖子演示第二个场景时，A1 直接命中缓存，既省额度又秒出，现场更流畅。

## 9. 三 Agent Prompt 全文（直接复制；temperature 0.2，只输出 JSON）

### 9.1 `prompts/extract.txt`（A1 解构，用 fast 档）



```
你是资深工科技术编辑。阅读这篇知乎经验帖，解构作者"在什么场景、用什么方案、受什么约束"解决问题，

供后续与另一位读者的真实场景对比。只输出 JSON：

{

&#x20; "scene": "作者面对的问题与应用场景，一句话",

&#x20; "originalSolution": \["原方案步骤1","步骤2"],

&#x20; "constraints": \["作者当时的器件/速率/成本/工期等约束"],

&#x20; "keyParams": {"参数名":"参数值"},

&#x20; "boundaries": "适用边界，什么情况不适用，一句话"

}

只基于原文，不编造；信息不足字段填 null。

标题：{title}

正文/摘要：{content}
```

### 9.2 `prompts/diff.txt`（A2 差异，用 thinking 档）



```
你是严谨的工程方案评审。已知经验帖原始场景方案(A)与读者真实场景(B)，对比迁移异同与照搬风险，只输出 JSON：

{

&#x20; "same": \["可直接复用的相同点，≤3条"],

&#x20; "differences":\[

&#x20;   {"dim":"维度(器件/速率/数量/负载/功耗/环境/成本/工期)","origin":"A的情况","mine":"B的情况","impact":"该差异的技术影响，一句话"}

&#x20; ],

&#x20; "risks": \["若直接照搬A，在B下会出现的具体问题，≤4条"]

}

differences 至少2条；impact 必须具体，禁止"可能不适用"这类空话。

(A)原帖解构：{origin\_json}

(B)读者场景：{user\_scene}

读者约束：{user\_constraint}
```

### 9.3 `prompts/transfer.txt`（A3 迁移，用 thinking 档，最关键）



```
你是带过多届电子/机械竞赛队的资深工程师。基于"原帖解构、差异风险、读者场景约束"，产出可直接照做的迁移方案，只输出 JSON：

{

&#x20; "steps":\[

&#x20;   {"step":1,"title":"动宾短语","detail":"具体怎么做：参数/寄存器级动作/代码思路/选型","why":"必须引用 differences 中某个 dim，说明因该差异而这样改"}

&#x20; ],

&#x20; "bomOrParams":{"物料或关键参数":"取值"},

&#x20; "summary":"一段话：相比原帖最关键的改动是什么、为什么"

}

硬性规则：

1\. steps 3\~6步、顺序可执行，detail 具体到能动手，禁止"注意稳定性"类空话；

2\. 每步 why 必须显式对应一条差异维度，形成"差异→对策"闭环；

3\. 工科场景给量化值（频率/缓冲区/线宽/电流/扭矩区间）；信息不足给区间并标注假设；

4\. 不输出与差异无关的通用套话。

原帖解构：{origin\_json}

差异分析：{diff\_json}

读者场景/约束：{user\_scene} / {user\_constraint}
```

### 9.4 稳健性处理（写进 llm\_base）

剥 \`\`\`json 围栏 → json.loads 失败则重试 1 次 → 再失败把原文包成 `{"fallbackText":...}` 让前端降级展示，**永不白屏**。每个 prompt 末尾固定追加：「输出前自检：是否合法 JSON；A3 每个 step.why 是否都引用了差异维度」。

| --- | --- | --- |
| Q1 意愿与表达门槛 | 要用户自己写场景，没意愿 / 不会写 / 懒得写，主链路第一步就断 | **低门槛输入三态**：①粘贴代码·报错·截图→AI 反推场景 ②结构化填空(芯片/下拉/多选) ③AI 反问 2–3 个选择题。把"表达"变成"粘贴 / 选择"。 |
| Q2 与直接问 AI 无区别 | 不做奖励机制，产品≈贴帖让 AI 出方案，和 ChatGPT 没差 | 单次交互确实是 wrapper；**真正差异化是"一帖千面"的场景 corpus / 网（知识应用图谱）**——通用 AI 每次对话是孤岛，没有"别人同处境得到什么"。差异化在累积，不在单次。 |
| Q3 AI 答案不准 | AI 生成内容不一定对，准确性不能保证 | 不追求"AI 全对"，追求**可核查 + 可追溯 + 集体交叉验证**：①锚定原帖真实方案(检索增强) ②每步 why 引用差异维度(可审计) ③人环验证网(读者标"有用 / 不准")。 |
| Q4 原帖不准 / 知乎多废话 / 怎么嵌生态 | AI 锚定的原帖可能本身不准；知乎很多帖是提问·吐槽·新闻·废话；如何嵌入知乎 | **质量门 ingestion**：只让"含真实可迁移解法"的帖进 corpus，借知乎自有信号(赞/藏/作者等级/盐选/专业领域阈值)+社区标"无可迁移解法"踢出；垂直优先吃工科。嵌入=做"层"不做"替代品"：reader 应用层(接收藏夹)+creator 反哺(场景网 enrichment 答主内容，接致知/盐选)。 |

### 19.2 收敛后的产品画像（一句话）
**不是"任意知乎帖→AI 答案"的包装器，而是"专业解法内容的场景应用网"**：质量门 ingestion + 低门槛贡献 + 人环验证(根+叶都验) + 双向嵌入知乎(reader 应用层 + creator enrichment)。每被质疑一次，边界收一层，但站得住的理由多一层。

### 19.3 对开发的强制约束（已并入 §3）
- 入口必须有质量门：低于质量阈值的帖不进入迁移 corpus。
- 场景输入必须支持"粘贴推断 / 结构化 / AI 反问"至少两种。
- 方案必须带验证状态字段（AI 草稿 ↔ N 人验证通过），并支持"标记不准 / 补充实测"。
- creator 反哺通道（"你的回答被应用到 N 个场景"）作为 P2 预留，架构上不阻塞。

### 19.4 路演话术修正
- 旧：帮用户"省得重来"、把文章压短。
- 新：我们是"真实场景 × AI 起草 × 人验证"的知识应用网络；不为废话帖做迁移，只放大真正有用的经验；一篇帖积累一千个真实场景，就是一张越用越准的网。

## 20. 帖子判断规则与场景上传交互（2026-09-09 设计定稿）

> 本节将 §19 辩论结论落地为可执行规则：① 哪些帖值得进迁移 corpus（质量门）；② 用户怎么"愿意"上传真实场景（交互形式）。§11.2 的 SceneForm 已按 §20.2 改写。

### 20.1 帖子判断规则（质量门 ingestion）

分两层：硬过滤（一票否决）+ 软评分（准入/排序），再叠加社区信号兜底。

#### 20.1.1 硬过滤（自动排除，不进 corpus）
| 条件 | 排除理由 |
| --- | --- |
| 内容类型 ∈ {想法, 视频无文稿, 纯新闻转发} | 多为吐槽/情绪/资讯，无可迁移解法 |
| 语义分类 ∈ {提问求助, 纯吐槽, 广告软文, 新闻资讯} | 不是"分享解法"的帖 |
| 正文 < 200 字且无步骤/代码/参数 | 信息密度不足以迁移（除非高赞高藏破例）|

#### 20.1.2 软评分（Agent0 分类 + 元数据融合）
后端跑轻量分类 Prompt（Agent0），读 title+content 输出：
`{ hasSolution: bool, solutionType: "step_by_step|experience|pitfall_log|tutorial|question|rant|news|opinion|ad", confidence: 0~1, keySolutionSummary: str }`

综合分：
`score = 0.30*参与质量 + 0.25*作者可信 + 0.30*解法置信 + 0.15*话题契合`
- 参与质量：normalize(赞同, 收藏, 评论)，**收藏权重最高**（"存=想用"是最强信号）
- 作者可信：等级/专业认证/盐选 → 0~1
- 解法置信：Agent0 的 `confidence`
- 话题契合：是否在专业解法垂直（工科/编程/硬件/职场方法论…）→ 0/1

准入阈值：`score ≥ 0.6` 进 corpus；`0.4–0.6` 标"待社区确认"；`< 0.4` 排除。

#### 20.1.3 社区信号兜底（网自净）
- 读者可标"**此帖无可迁移解法**"，标率 > 30% → 降级/踢出。
- 一篇帖若攒出多个高验证场景 → 自动升权（网络效应正循环）。

#### 20.1.4 Demo 与真实态
- Demo：3 篇种子帖人工验过，`score` 预置高位，不跑实时分类也能演示。
- 真实 API：拉收藏/搜索后跑 20.1.1–20.1.3；分类不准可由社区标"无可迁移解法"纠偏。
- 举例：种子帖1《STM32串口踩坑》（回答+1200赞+300藏+含代码步骤）→ score≈0.85 进；某《如何看待XX裁员》想法（rant）→ 硬过滤排除；某《求助：STM32卡死》提问帖 → `solutionType=question` 排除（可引导用户自己写完解法再迁移）。

### 20.2 场景上传交互形式（制造分享欲）

核心原则：**不叫"填表"，叫"说说你正卡在哪"；不先要信息，先给价值；让分享变成"我给这张网添了一种用法"的归属感。**

#### 20.2.1 触发时机（动机最强处捕获）
- 收藏台每张卡片主按钮 **"适配到我的场景"**。
- 用户收藏/点开一篇解法帖时，卡片底部轻量内联提示（非弹窗）：*"你收它是想用在哪？一句话就够 👉"* —— 顺手即点。

#### 20.2.2 输入区三态（怎么舒服怎么来）
| 路径 | 交互 | 文案（口语化，非表单感） |
| --- | --- | --- |
| ① 粘贴即懂 | 大块 paste/拖拽区，可贴代码/报错/截图 | *"把你现在的代码或报错直接丢进来，AI 帮你提炼处境"* |
| ② 选 chip 起头 | 4 个贴近的快捷场景芯片（来自种子） | *"或者挑个接近的："* → 一点即填好开头 |
| ③ AI 陪聊式反问 | 用户只打一句模糊的话，AI 像 senior 工程师追问 1–2 个选择题 | *"听上去在做智能车？用的啥主控？卡在接收还是处理？"* |

#### 20.2.3 制造"分享欲"的三个机制（非积分，是即时反馈）
1. **价值即时兑现**：边输入边显示 *"AI 正把你的处境和原帖对上…"*，生成后立刻给三件套预览——奖励是当下产出的方案，不是延迟的虚拟币。
2. **"你进了这张网"的归属感**：生成后一句 *"你的方案已加入《STM32串口》场景网，目前全网第 7 个场景"* 或 *"你和另外 6 个做智能车的人处境相似"* → 贡献骄傲 + 同类认同。
3. **对比好奇心（FOMO）**：*"看看别人在同一帖下的处境 →"* 点开看（匿名）其他场景 → 好奇驱动"我也要加一个"。

#### 20.2.4 去生硬的具体做法
- 无强制必填：除最小输入外全部可选，智能默认。
- 文案去表单化：成功提示写 *"这张网因你 +1"*，不写"提交成功"。
- 零门槛身份：匿名贡献，不逼登录/填资料。
- 进度叙事：把"填写"包装成"帮原帖多长出一种用法"。

#### 20.2.5 页面流（对应 §11.2 AdaptBench）
```
收藏台卡片 → "适配到我的场景"
  → AdaptBench 打开，OriginCard 自动解构(A1)
  → 底部友好输入区：粘贴 / chip / 自由说（三选一）
  → 输入后 AI 要么反推、要么追问 1–2 句
  → 点"生成我的方案" → 三件套
  → 生成后："已加入场景网 +N + 看看别人的相似场景" + 可选"补充实测/标记不准"
```
